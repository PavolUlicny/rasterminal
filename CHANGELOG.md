# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- Assimp 6.0.5 as a fallback for formats without native loaders. It imports static geometry, scene transforms, common materials and textures. OBJ, PLY, STL and glTF/GLB remain native-only.
- Pixel rendering through the kitty graphics protocol (kitty, Ghostty, WezTerm and others). The frame is a real image instead of half-block cells, which multiplies the resolution by the cell size, roughly 10x16 at a typical font. It renders at the window's native pixel resolution. Locally the pixels travel through shared memory, so almost nothing crosses the terminal pipe per frame; over ssh they go inline, compressed. The image follows a font-size change mid-session and is removed from the terminal on exit.
- Pixel rendering through sixel graphics, which reaches terminals that render sixel but not the kitty protocol: xterm with sixel enabled, foot, mlterm, Windows Terminal 1.22 and later. The image renders at native resolution and repaints in full on every change. Its pixels are always the fixed 240-color xterm palette, so `--color` affects only the HUD line there. The image never paints the last terminal row, since one touching it scrolls the screen every frame, and it is capped to the largest size the terminal advertises, since xterm discards an oversized image rather than clipping it. Anything a limit leaves smaller than the window is centered.
- `--graphics kitty|sixel|blocks|auto` chooses the backend. `auto`, the default, prefers kitty, then sixel, then half-blocks. Support comes from a bounded startup query to the terminal itself, never from environment variables. Forcing `kitty` or `sixel` is an error when that query goes unanswered, since a terminal without the protocol discards the escapes silently and would show an empty screen; `blocks` skips the query. Neither pixel backend works under tmux or GNU screen, which do not pass the protocols through. The query now runs on Windows too.
- Frames are wrapped in the synchronized-output escape pair (mode 2026), so terminals that implement it paint each frame atomically instead of showing a partly applied update. This matters most for sixel, which has no atomic image replacement, and for half-block full redraws. A resize's screen erase now travels inside the next frame, so the window swaps straight to it instead of blanking while the frame renders. An idle frame writes nothing at all on every backend.
- `--first-person`/`--no-first-person` selects a free-flying camera instead of the turntable (default off). There is no gravity, collision or ground plane: it flies, and passes through geometry, which is the point, since the turntable can only look at a model from outside its bounding sphere. Only the camera bindings change. `W`/`A`/`S`/`D` move along the view direction, `E` and `V` rise and fall along world up, the arrows and a mouse drag look, and `+`/`-` and the wheel set movement speed instead of zoom. Speed scales with the model, so a key feels the same at any size. Pitch stops at straight up and straight down, and `--pitch` is clamped to that limit here. The camera cannot fly further out than the scroll wheel already reaches in orbit mode, and `R` returns to the launch view. Auto-rotation becomes a slow panorama from wherever the camera stands, and `--bench` ignores the flag entirely. Only one key moves the camera at a time, so there is no diagonal flight: a terminal sends no key releases and the operating system repeats only the most recently pressed key. Drag the mouse to look while you move.
- `--first-person-speed FACTOR` sets the initial movement speed as a multiplier of the model-scaled default, in [0.05, 20] (default `1`), the same range `+`/`-` and the wheel move within. It requires `--first-person`, since that mode cannot be entered mid-session. `R` restores it.
- `--yaw`, `--pitch` and `--zoom` set the initial camera pose, and together reach any view the mouse can. `--yaw` takes degrees in [-180, 180] (default `0`), positive turning the model left on screen. `--pitch` takes degrees in [-180, 180] (default `-17.2`): negative looks down from above, `-90` is top-down, and past 90 either way the model is upside down. `--zoom` takes an apparent-size multiplier of the auto-fit framing in [0.2, 100] (default `1`), bounded by the scroll wheel's range. All three also set the `--bench` camera, and `R` returns to them.
- 256-color output on terminals without 24-bit color, quantized per pixel from the same truecolor pipeline by perceptual (CIELAB) nearest-color matching, so dark and muted colors keep their hue instead of collapsing into the gray ramp the way plain RGB distance sends them. Exact palette colors, the default black background among them, map to themselves. Terminals detected as truecolor keep byte-identical output.
- Color capability is detected at startup from the environment, first match winning. `TERM=dumb` is rejected outright, even against a `COLORTERM` claiming truecolor. Real GNU screen (a non-empty `STY`, or a screen-family `TERM` with no `TMUX`) is floored to 256 colors before `COLORTERM` is read, since the inherited value describes the outer terminal and screen 4.x renders 24-bit color as garbage; tmux is exempt, and screen 5 can force truecolor with `--color`. Then `COLORTERM=truecolor` or `24bit`, a `TERM` truecolor hint such as the `-direct` terminfo family, or a `TERM` naming a known truecolor terminal (kitty, WezTerm, Alacritty, Ghostty, foot, Contour) selects 24-bit. Anything else gets 256 colors, as does an unset `TERM`, except on a native Windows console. Those terminal names keep ssh sessions on 24-bit, since ssh does not forward `COLORTERM`; a truecolor terminal not identifiable from `TERM` needs `--color truecolor` there.
- `--color truecolor|256|auto`, with `24bit` accepted for `truecolor`, overrides that detection. Forcing a mode does not bypass the `TERM=dumb` rejection or the Windows VT gate. Under a pixel backend it affects only the HUD line, since kitty images are always 24-bit and sixel images always 240-color.
- `--spin-speed` and `--spin-direction left|right` set the auto-rotation rate in degrees per second and the way the model's front face moves on screen. Both apply whenever spinning is active, and neither implies `--spin`. The defaults, 45 degrees per second and `left`, match the previous fixed behavior.
- `--input`/`--no-input`. Under `--no-input` every keyboard and mouse binding is ignored except the quit key: `Q` and Ctrl+C still quit. Nothing else changes. Auto-rotation keeps running if `--spin` started it, the HUD updates, and the render reflows on a resize. The mouse stays claimed by the viewer, so a drag over the render neither orbits nor paints a text selection. Input is still read so it cannot pile up in the terminal, it is just not acted on.
- `--no-spin`, `--ao` and `--hud`, so every boolean state flag now comes as a `--flag`/`--no-flag` pair with the later flag winning and the default state always spellable.
- `install` and `uninstall` targets, following the GNU directory layout with prefix and `DESTDIR` overrides. They install the binary, the man page, and the license and notices.
- A man page, `man/rasterminal.1`.

### Changed

- Building from source now requires CMake 3.22 or newer, replacing the 3.16 floor. The stock CMake packages in Ubuntu 20.04 and Debian 11 no longer meet the requirement.
- Rendering is much faster, most of all when the picture is large and the model fills it, which is what the pixel backends put front and centre. Phong at 1920x1080 on a 16-thread laptop, measured with `--bench`: the Sponza atrium 61 ms to 9 ms, and zoomed into it 248 ms to 21 ms; a 645k-triangle city with 4K textures at 3840x2160 72 ms to 39 ms; a dense jungle scene 202 ms to 94 ms; a 10-million-triangle sphere 61 ms to 36 ms. Flat shading gains the same way and backface culling turned off gains most of all; wireframe is unchanged. The picture is unchanged apart from floating-point rounding and the edge-coverage fix listed below. Underneath, the opaque pass now picks between two forms each frame, binning large triangles into screen tiles so every pixel is shaded once rather than once per overlapping surface, and keeping the per-triangle pass where triangles are pixel-sized.
- Sending a frame to the terminal is about four times faster on the pixel backends, where at high resolution it had grown to cost more than drawing the frame did. On a 16-thread laptop, kitty's inline transport went from 18.5 ms to 4.1 ms at 1920x1080 and from 73.7 ms to 13.5 ms at 3840x2160, while putting slightly fewer bytes on the wire; sixel went from 4.9 ms to 1.3 ms and from 18.2 ms to 4.3 ms. Compression, palette conversion and sixel encoding now run across the worker threads the renderer already owns, each producing byte-for-byte what the single-threaded code produced. `--bench` cannot show any of this, since it never sends a frame.
- Scenes with alpha-blended surfaces render two to eight times faster, and looking through several layers no longer collapses the frame rate. Phong at 1920x1080 on a 16-thread laptop: the Khronos alpha-blending test 22 ms to 3 ms, a candle in a glass shade 29 ms to 11 ms, a glazed vase 17 ms to 10 ms. Most of the gain is work sharing, since blended geometry is usually a few large surfaces grouped together by material, so one thread used to take almost the whole frame while the rest went idle. The picture is unchanged beyond floating-point rounding.
- glTF and GLB models containing many mesh primitives open several times faster: a 645k-triangle city of 113 primitives went from 1.9 s to 0.6 s on a 16-thread laptop, a car from 0.31 s to 0.18 s. A single-primitive model is unaffected. The loader used to ask its vertex and triangle arrays for exactly the room one more primitive needed, which makes a growing array reallocate and copy everything read so far every time, so a hundred primitives moved gigabytes for a mesh of tens of megabytes.
- The kitty and sixel backends now use every core by default instead of at most four. On a 16-thread laptop a 645k-triangle city at 3840x2160 went from 175 ms a frame to 73 ms. The old default was chosen when a frame was a few tens of thousands of half-block pixels; a pixel backend at native resolution renders a hundred times that. Half-block output keeps the old default, since those frames already finish well inside the frame cap and the extra threads would cost roughly twice the CPU for latency nobody is waiting on, which matters on battery. Loading a model now uses every core on every backend, and `-j` overrides as before.
- The half-block backend no longer redraws a frame when nothing has changed. It used to re-rasterize the whole model every frame for as long as the viewer was open, motionless or not. That was invisible on screen, since an unchanged frame wrote almost nothing to the terminal, but it cost about 2% of a core on a small model at the default cap, scaling with the mesh. Any input, auto-rotation, or a resize resumes drawing immediately, and under a bare `-f` an idle viewer now paces itself instead of running flat out. All three backends now agree, down to the frame-rate reading in the HUD holding its last real value while idle.
- The default frame cap is 30 fps rather than 60. A model viewer in a terminal has no need of a display-refresh frame rate. Everything that moves draws less often, in proportion to how far the new cap sits below the rate the model was managing; one already drawing below 30 fps is untouched. What the frame loop paces slows to match, input latency most visibly: a keypress is noticed within 33 ms rather than 17. `-f 60` restores the previous behavior.
- An ASCII-classified STL file containing a line longer than 64 KB is now rejected up front, because parsing such a line costs a large multiple of its size in memory (measured above 1 GB for a 52 MB single-line file). Such a line is either garbage or content the format ignores; no real STL comes near that length. Files at or under 64 KB skip the check.
- The HUD is now a full-width status bar in three zones rather than one left-aligned line of uniformly grey fields: the model name on the left, the render state centered, and the toggle tags with the live numbers against the right edge. The `light:`, `bg:` and `wf:` labels are gone, since those values are recognizable on their own. Fields carry a visual hierarchy instead of one color: values are brighter than labels and separators, the active shading mode takes a soft cyan accent, spin, cull and texture became compact tags lit in that accent when on, and in wireframe shading the wireframe color's name renders in its own color. On a terminal too narrow for the full bar, fields are dropped in order of how redundant each is with the picture itself, rather than clipped wherever they crossed the right edge; last to survive is the fps reading, which has no visual stand-in and still shows on a terminal about ten columns wide. The bar is measured in terminal columns rather than bytes, so a name in a non-Latin or East Asian script still fills it to the right edge.
- Long model names no longer crowd the HUD off the screen. A name is shortened to 24 bytes by replacing its middle with `...`, so a longer one reads as `a_very_long...l_name.stl`. The middle goes rather than the end so the extension survives, and the cut never lands inside a character; the trade is that two names agreeing at both ends now display alike. A filename is also sanitized before display, each offending byte replaced by `?`: control characters, the C1 range a terminal can read as escape-sequence introducers, bytes that are not valid UTF-8 (a filename is an arbitrary byte string on Unix), and the invisible and direction-changing format characters, which can silently reorder what a name appears to say.
- Escape no longer quits; `Q` and Ctrl+C are the quit keys, matching the usual terminal convention. Escape on its own now does nothing, and any escape sequence the viewer has no binding for is consumed whole and ignored. Previously function keys, the navigation and editing cluster, modified or application-mode arrows, alt chords, X10-style mouse clicks, terminal replies, and any sequence split across reads all read as an Escape press and exited the viewer. Mouse reports were the exception, mishandled two ways: an incomplete one was discarded silently, while a malformed one was cut short at whatever byte broke the format, leaving the rest to arrive as ordinary typing (the digits of a coordinate switching shading mode, for instance). Input is now buffered and parsed as a unit, so a long reply, or one split across frames by a slow connection, is consumed whole rather than acted on halfway through.
- Some input limits remain after that rework, all of them cases where the viewer cannot tell a machine from a person. A sequence longer than 1024 bytes, in practice a clipboard or status reply rather than a keypress, cannot be held in full: the viewer skips ahead to its end, and anything typed while it arrives is lost with it. Only the reply's own ending stops the skip. One that never ends is skipped only while bytes keep arriving fast enough to look like a stream rather than a person, about 256 a second, and is given up on about two seconds after they fall below that. Typing does not hold it open; a mouse drag does, since terminals send those far faster. Ctrl+C escapes throughout, being a signal rather than a keypress. A short sequence whose bytes are spaced wider apart than the reassembly window is read as ordinary typing instead, because at that spacing it is indistinguishable from someone typing those same characters.
- `R` now resets to the flag-specified launch state instead of factory defaults: shading, lighting, background, wireframe color, spin, backface culling and texturing return to the values their flags selected, joining the camera, which already returned to the `--yaw`/`--pitch`/`--zoom` view. The reset also cancels a still-held camera key, which could previously keep moving the camera for up to 100 ms afterwards. With no flags passed the reset target is unchanged.
- `--cull` and `--texture` no longer take an `on|off` value. They are paired boolean flags now, `--cull`/`--no-cull` and `--texture`/`--no-texture`, with the later winning. The `-c` and `-t` short flags and the boolean value spellings (`on`/`off`, `1`/`0`, `true`/`false`, `yes`/`no`, `y`/`n`) go with the value form: `--cull=on` is now a does-not-take-a-value error, `-c` and `-t` are unknown flags, and a token after the flag is read as the model operand.
- Interactive rendering now fails with a clear error, rather than emitting escape garbage, on any terminal it cannot draw to: stdin or stdout not being a terminal (which previously also set raw mode on a non-terminal stdin), `TERM=dumb`, or a Windows console that cannot enable VT escape-sequence processing. `--bench`, `--help` and `--version` keep working with redirected streams. On Windows, `--version` now switches the console to UTF-8 only when stdout is a VT-capable console, so a redirected, piped or legacy-console run leaves the code page untouched.
- Lit surfaces now pass through a soft-knee highlight rolloff before display, so bright, untextured, flat-lit or strongly emissive areas keep their shading gradient instead of clipping to flat white. The curve is identity below the knee (0.7) and rolls off above it, leaving midtones and shadows unchanged. Unlit materials and the wireframe, HUD and background are unaffected.
- Slightly smaller per-frame terminal output: the incremental redraw no longer writes a cursor-advance escape when a row's changed pixels are followed by an unchanged run reaching the right edge. The rendered result is identical.

### Removed

- The Makefile. CMake is now the only build system, which is the one of the two that ever built on Windows. Nothing about the resulting binary changes: the two were verified to compile and link with identical flags first, and to produce the same code. `make` becomes `cmake -B build && cmake --build build -j`, `make test` becomes `cmake --build build --target check`, `make install` and `make uninstall` become `cmake --install build` and `cmake --build build --target uninstall`, and `make portable`/`dist`/`debug` become the `portable`, `dist` and `debug` presets or their `-D` equivalents. The binary now lands in the build directory rather than the repo root.
- The 1-indexed numeric value aliases for `--shading`, `--bg`, `--lighting` and `--wireframe-color` (`-s 3` for `-s phong`, or `--bg 2` for `--bg gray`). Use the named values; a numeric value is now an invalid-value error.
- The shadow map and the `--no-shadow` flag. A single auto-fit model with no ground plane has nothing to receive a cast shadow, so the feature cost load time and frame time without giving a model viewer anything. Lit surfaces now use every configured light uniformly and baked ambient occlusion still darkens crevices; the default look is slightly flatter than before. `--no-shadow` is now an unknown-flag error.

### Fixed

- PLY now accepts only the three format tokens in the specification instead of treating missing or unknown encodings as ASCII.
- `cmake -B build -DCMAKE_CXX_COMPILER=clang++` now links. Setting only the C++ compiler left the vendored C sources on the system `cc`, and because CMake enables link-time optimization per language, the two compilers produced LTO objects in formats the other's linker cannot read. Those sources now build in their own object library with LTO off, as they always did under Make. Building with Clang no longer requires naming `-DCMAKE_C_COMPILER=clang` as well, though it is still worth doing.
- CMake builds now compile and link with the same flags Make does, verified token by token across every variant and both compilers. The vendored C sources were picking up the C++ flag set, including link-time optimization, `-fno-rtti` and the aggressive options only the project's own code opts into, and were missing `-std=c11`. Neither build system's link line carried the other's optimization flags, which under link-time optimization is where code generation happens, so the two could emit different machine code from identical sources.
- Triangles no longer bleed a little past their own edges. The rasterizer used to carry each triangle's edge values along a row by repeated addition, which accumulates rounding error: after a few hundred pixels a triangle nearly edge-on to the scanline covered up to a dozen pixels beyond where it actually ends, hiding whatever was behind it. Edge values now come from the pixel's own coordinates instead. Surfaces also show about a third fewer pinholes at shared edges, measured across 34 models.
- A model carrying a non-finite texture coordinate is now rejected at load, like one carrying a non-finite vertex position. Such a coordinate reached the texture sampler, where converting it to a texel index read memory outside the image, so a malformed file could crash the viewer or draw arbitrary memory as color. Only binary formats can deliver one, and no real model has one.
- A glTF or GLB file declaring a vertex attribute with fewer components than its role needs, a 2-component POSITION say, no longer fills the missing components from uninitialized memory, which made such a model's shape or shading unpredictable. The attribute now counts as absent: a POSITION like that skips its primitive, and the rest fall back exactly as they do for a file that omits them.
- Several valid STL files that were previously rejected now load. The loader classifies a file as ASCII or binary once and parses it with that format's reader, where it used to hand the file to a vendored entry point that re-detected the format by a different heuristic, so a file the two disagreed on was parsed wrong and rejected. Now loading: an ASCII file whose first `facet` keyword or first line break sits past the 256th byte, a binary file whose 80-byte header comment happens to mention `solid` and `facet normal` next to a newline, an ASCII file opening with a blank line or a UTF-8 byte-order mark, and one whose `solid` keyword is capitalized. Separately, classifying a file shorter than the 80-byte STL header no longer examines bytes beyond what was actually read, which made the decision depend on uninitialized memory; no load outcome changes from that, since the only files those bytes could sway are rejected either way.
- Input decoding no longer stalls rendering while a key sequence is still arriving. It used to wait mid-sequence for the next byte, up to 50 ms per byte, so on a busy or high-latency connection an arrow key or a mouse drag could visibly drop the frame rate. Decoding no longer waits at all on POSIX; what remains is the work of reading, measured at 3.1 ms for a whole frame's worth of the most expensive input shape, against the 33 ms of a frame at the default cap. The Windows console API offers no equivalent guarantee.
- Mouse handling is steadier. A wheel notch sent with a modifier held now zooms; it was previously mistaken for a drag, which snapped the camera by the distance from wherever the pointer last was. A horizontal wheel is now ignored outright rather than read as that same spurious drag. A malformed report is ignored whole, and every form the SGR extension does not allow is rejected: a missing, zero or absurd coordinate, a button code outside the eight bits the encoding has, a press or motion naming no button, a motion or wheel report in the release form, extra parameters, and parameters that are not all numeric. A release naming no button is still honored, since that is how some terminals report one. Previously a report whose parameters were all numeric was acted on whatever they said, and since a press sets the point a drag is measured from, nothing looked wrong until the camera jumped on the next motion report. A drag delta larger than the terminal is now re-seeded rather than orbited, and a drag that begins without its opening report starts from the pointer's current position instead of jumping.
- Characters with no binding no longer cancel a held camera key. Any such character arriving mid-movement used to stop the camera until that key was pressed again, most visibly when pasting text or when a terminal reply arrived. Pressing another key still stops the movement and always will: the operating system repeats only the most recently pressed key, so the held key stops sending anything at all.
- On Windows, a console that cannot report its size no longer produces a garbled or one-column render. The failure is now detected, as is a console reporting an empty window rectangle, and the viewer falls back to 80x24 as it does elsewhere. The size was previously read from uninitialized memory.
- STL models now load upright instead of pitched 90 degrees sideways. STL carries no orientation metadata and its ecosystem convention (CAD, 3D printing) is Z-up while the renderer is Y-up, so the loader now remaps STL coordinates at load. OBJ and glTF are Y-up by specification and PLY is treated as Y-up, so those formats are unchanged.
- A `--threads`/`-j` value above the hardware thread count is now clamped to it everywhere. Only the render worker pool clamped before, so the `--bench` report header printed the unclamped request and model loading could spawn the full requested number.
- `--bench-size WxH` now rejects dimensions whose pixel count would exceed the addressable range. Such a value previously crashed a 32-bit build, where the count wrapped and produced a tiny framebuffer that rasterization then wrote past. Each axis was, and still is, capped individually.
- Release builds (`-march=native`) no longer fail with newer Clang on AVX10-capable CPUs, where Clang's benign "avx10.1-256 will be promoted to avx10.1-512" warning was fatal under `-Werror`.
- Model files of 2 GB or more now load on Windows, where file sizing used the C library's 32-bit `ftell`, so a binary STL that large was always rejected at its file-size validation and a glTF external image that large failed to read. 32-bit builds, whose address space can never fit such a model, now report the normal load failure everywhere.
- Horizontal orbit no longer reverses when the model is viewed upside down. After pitching the camera past a pole, dragging left or right, and the `A`/`D` and arrow keys, moved the model opposite to the input. Yaw is now inverted while the view is upside down, matching Blender's turntable, so the model follows the drag continuously through a pole.
- The HUD frame-rate counter read `0 fps` at startup until the model was moved, and read too low at uncapped or very high frame caps, because it discarded every frame faster than 1 ms and light models rarely produce a slower one. Sub-millisecond frames now count, and the displayed value refreshes at a fixed 10 Hz so it stays readable.
- glTF models using the ratified `KHR_meshopt_compression` extension, rather than the older draft `EXT_meshopt_compression` name, loaded no real geometry, since the vendored cgltf recognized only the draft name. cgltf is refreshed to a commit that parses both, and the extension's `COLOR` vertex filter is now decoded.
- glTF sparse accessors read as zero or empty instead of resolving the sparse data, a latent bug in the cgltf version that refresh replaces.

## [v0.1.0-alpha.1] - 2026-06-27

First public prerelease.

### Added

- CPU rasterization pipeline: model/view/projection transforms, perspective-correct triangle rasterization, z-buffer depth testing, backface culling, Blinn-Phong lighting, and order-independent alpha-blended transparency (exact per-pixel A-buffer)
- Shading modes: wireframe, flat, and Phong
- Shadow mapping (alpha-cutout aware) and baked ambient occlusion
- Texturing: bilinear sampling with per-texture wrap modes (Repeat/Clamp/Mirror), alpha cutout, and normal/metallic/emissive/occlusion maps
- Compressed texture and geometry support: KTX2/Basis (ETC1S/UASTC), WebP, Draco mesh compression, and meshopt-compressed buffer views
- Model formats: OBJ/MTL, PLY (ASCII and binary LE/BE), STL (ASCII and binary), and glTF 2.0 / GLB
- Multithreaded worker pool driving the opaque, transparent-accumulate, and resolve phases
- Unicode half-block (`▀`) output with 24-bit ANSI color; two vertical pixels per terminal cell
- Interactive controls: keyboard plus mouse drag-orbit and scroll-zoom, auto-rotation, and a HUD status line
- CLI flags for initial shading/background/lighting/wireframe color, culling, texturing, threads, frame cap, headless benchmarking, crease angle, and the `--no-shadow`/`--no-ao`/`--no-hud` toggles
- Cross-platform support: Linux, macOS, and Windows, including 32-bit (ILP32) builds
- Two build systems (Make and CMake) each with release, portable, and dist (self-contained) variants
