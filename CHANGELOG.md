# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- Pixel rendering through the kitty graphics protocol. On a terminal that implements the protocol (kitty, Ghostty, WezTerm among them), the frame is now displayed as a real image instead of unicode half-block cells, multiplying the effective resolution by the cell pixel size (roughly 10x16 at a typical font). The frame is rendered at 0.75 of the window's pixel resolution by default and stretched back over the same cells by the terminal; a new `--graphics-scale` flag sets the fraction anywhere in [0.05, 1], with 1 rendering at native resolution, trading sharpness against per-frame shading work. The scale never affects the half-block backend, and combining it with an explicit `--graphics blocks` is an error. Support is detected at startup by querying the terminal itself, batched with a cell-size request and bounded by a device-status report every terminal answers, so detection cannot hang and never guesses graphics capability from environment variables (the one environment check is the tmux and GNU screen gate, which skips the query under a multiplexer); the query runs before the interactive input machinery takes over stdin, so its replies cannot be misread as keypresses. A new `--graphics kitty|blocks|auto` flag overrides the choice: `auto` (the default) picks kitty when detected, `blocks` skips detection entirely, and `kitty` fails with an error when the terminal does not answer the query, because a terminal without the protocol silently discards the escapes and would show an empty screen. Where the terminal can reach this machine's memory, the pixels travel through a POSIX shared-memory object and only a tiny escape naming it crosses the terminal pipe per frame; that ability is itself verified with the terminal at startup (the query names a real object and the terminal says whether it could open it), so the other case, an ssh session or a sandboxed terminal with its own private memory namespace, is detected reliably rather than guessed from the environment, and gets the frames zlib-compressed and sent inline, base64-encoded, at a fraction of their raw size on the wire. While idle the HUD keeps showing the last real rendering rate rather than a meaningless idle-loop figure. While nothing changes on screen, no image is retransmitted and no frame is rendered at all, so an idle viewer costs no bandwidth and near-zero CPU, which matters most over ssh; any input, auto-rotation, or a resize resumes immediately. The image fills every cell above the HUD row and scales with the window; a font-size change mid-session is picked up on terminals that report their window pixel size, and on those that do not but answer the standard cell-size query, the viewer asks and adopts the answer without ever waiting on it. The HUD keeps working exactly as in blocks mode. The displayed image is freed from the terminal on exit. Not available under tmux or GNU screen, which do not pass the protocol through; the half-block backend is used there. The `--bench` benchmark is unaffected (it never writes to the terminal), and rendering itself is identical in every respect: the same pipeline draws into the same framebuffer, only the way pixels reach the screen differs.
- `--first-person`/`--no-first-person` flag pair selecting a free-flying first-person camera instead of the turntable (default: off, the later flag wins). It is a fly camera, not a walk one: there is no gravity, no collision and no ground plane, so it passes straight through geometry, which is the point, since the turntable can only ever look at a model from outside its bounding sphere and large scenes are meant to be seen from within. The camera keys change and nothing else does: `W`/`A`/`S`/`D` move instead of orbiting, following where the camera is looking (look down, move forward, descend), `E` and `V` rise and fall along world up whatever the view is pitched to, the arrow keys and a mouse drag look around, and `+`/`-` and the wheel set the movement speed instead of zooming, since there is no longer an orbit radius for zoom to change. Looking follows the input rather than the model: dragging left turns the view left, which is the opposite of the turntable, where dragging left carries the model left. Movement speed is scaled to the model's size, so the same key feels the same on a millimetre-wide model and a kilometre-wide one, and it is shown in the HUD, which gains one field naming the mode. Pitch stops at straight up and straight down so the horizon never inverts, and `--pitch`, which accepts values past 90 in either direction, is clamped to just inside straight up and straight down when this flag is passed, the same limit the mode holds while looking. `--bench` is unaffected in every respect: it ignores this flag outright, since its camera spins each frame to sweep the model, which in first-person would pan the view off the model and time empty frames. The camera also cannot fly further from the model than the scroll wheel can already zoom out in orbit mode, so it cannot be flown off into empty space; it can still be pointed away from the model, since the bound constrains position and not view direction, and `R` returns to the launch view. There is no limit in the other direction: the camera flies through geometry freely, and because the near plane is scaled to the model rather than to the mode, a surface can pass inside it and vanish just before the camera reaches it. At `--zoom 0.2` the launch pose is already at the outer bound, so flying backwards does nothing until you move in, exactly as the scroll wheel does nothing at that zoom in orbit mode. Auto-rotation keeps working and becomes a slow panorama from wherever the camera stands rather than a turntable, at the `--spin-speed` and `--spin-direction` given. The `R` reset restores the position, the view direction and the movement speed along with everything else, and the launch pose is the one `--yaw`, `--pitch` and `--zoom` select, with `--pitch` clamped as above. Only one key moves the camera at a time, so there is no diagonal flight and no moving while turning from the keyboard; that follows from a terminal sending no key releases and the operating system repeating only the most recently pressed key, so a mouse drag is the way to look while moving. Without the flag every camera control behaves as before, byte for byte; `E` and `V` are unbound there and, like any other unbound key, do not interrupt a held movement key.
- `--first-person-speed` flag setting the initial first-person movement speed, as a multiplier of the model-scaled default, in `[0.05, 20]` (default `1`). The bounds are exactly the range `+`/`-` and the wheel move within, so no value it accepts is unreachable interactively and none it rejects is reachable. It requires `--first-person` and is an error without it, since that flag cannot be toggled during a session and the value could therefore never come into play (unlike `--spin-speed`, which stands alone because Space can start spinning later). The `R` reset returns the speed to this value along with the rest of the launch state.
- `--yaw`, `--pitch`, and `--zoom` flags setting the initial camera pose. `--yaw` takes degrees in `[-180, 180]` (default `0`); positive turns the model left on screen, the same direction as `--spin-direction left`. `--pitch` takes degrees in `[-180, 180]` (default `-17.2`, a rounding of the previous fixed `-0.3` rad tilt); negative looks down from above, `-90` is top-down, and values past 90 in either direction view the model upside down. `--zoom` takes an apparent-size multiplier of the auto-fit framing in `[0.2, 100]` (default `1`); `2` starts twice as close, and the bounds equal the range reachable with the scroll wheel. Together the three flags can express any camera view reachable interactively. They also set the `--bench` camera (the per-frame bench spin step is unchanged), and the `R` reset key returns to the flag-specified view.
- 256-color fallback: terminals without 24-bit color support now automatically receive xterm-256 palette output, quantized per pixel from the same truecolor rendering pipeline by perceptual (CIELAB) nearest-color matching, so dark and muted colors keep their hue instead of collapsing to the gray ramp (the palette's color cube has no chromatic entry with a nonzero channel below 95, and a plain RGB-distance match would send nearly all dark colors to gray). Exact palette colors, the default black background among them, always map to themselves. Capability is detected at startup from the `COLORTERM` and `TERM` environment variables (`COLORTERM=truecolor`/`24bit`, a `TERM` truecolor hint such as the `-direct` terminfo family, or a `TERM` naming a known truecolor terminal (kitty, WezTerm, Alacritty, Ghostty, foot, Contour) selects 24-bit output; any other non-empty `TERM` except `dumb` gets 256 colors; when `TERM` is unset or empty and `COLORTERM` carries no truecolor signal, the default is 256 colors, except on native Windows consoles which default to 24-bit). Terminals detected as truecolor keep byte-identical output. The known-terminal names keep ssh sessions (where `COLORTERM` is not forwarded) on 24-bit for those terminals; a truecolor terminal not identifiable from `TERM` is still detected as 256-color over ssh (force 24-bit with `--color truecolor`).
- `--color truecolor|256|auto` flag (with `24bit` accepted as an alias of `truecolor`) overriding the automatic color-capability detection; `auto` (the default) keeps detection. Forcing a mode does not bypass the `TERM=dumb` rejection or the Windows VT-capability gate. With the kitty graphics backend the image is always transmitted as 24-bit pixels, so the mode affects only the HUD line there.
- `--spin-speed` and `--spin-direction left|right` flags controlling the auto-rotation rate (degrees per second, any positive number) and the way the model's front face moves on screen. Both apply whenever spinning is active, whether started with `--spin` or toggled with Space, and neither implies `--spin`. The defaults match the previous fixed behavior: `left`, and 45 degrees per second (a rounding of the old hard-coded 0.8 rad/s, about 45.8). The `--bench` camera path is unaffected.
- `--input`/`--no-input` flag locking the interactive controls. Under `--no-input` every keyboard and mouse binding is ignored except the quit key: the shading, lighting, background, wireframe-color, culling, texture and spin toggles, camera orbit and zoom from the keys, the mouse or the wheel, and the `R` reset all do nothing. `Q` still quits, as does Ctrl+C. Nothing else about the session changes: auto-rotation keeps running when `--spin` started it, at the `--spin-speed` and `--spin-direction` given (Space simply can no longer start or stop it), the HUD still updates, and the render still reflows when the terminal is resized. The mouse is deliberately still claimed by the viewer, so a drag over the render neither orbits the camera nor paints a text selection across it. Input is also still read and decoded, so it cannot pile up in the terminal; it is simply not acted on. `--no-input` does not change which streams the viewer requires: stdin must still be a terminal, since `Q` has to stay reachable.
- `--no-spin`, `--ao`, and `--hud` flags, completing the paired-boolean convention: all six boolean state flags (`--cull`, `--texture`, `--spin`, `--ao`, `--hud`, `--input`) come as `--flag`/`--no-flag` pairs with the later flag winning, so the default state is always spellable and an earlier flag can be overridden. The existing `--spin`/`-S`, `--no-ao`, and `--no-hud` behave exactly as before.
- `install`/`uninstall` targets for both Make and CMake (GNU directory layout, `PREFIX`/`DESTDIR` overrides) installing the binary, man page, and license/notices
- Man page (`man/rasterminal.1`)

### Changed

- The default frame cap is now 30 fps instead of 60. A model viewer in a terminal has no need of a display-refresh frame rate. Everything that moves (auto-rotation, a mouse drag, a held camera key, first-person flight) now draws less often, in proportion to how far the new cap sits below the rate the model was actually managing: one that was holding the old 60 fps cap does half the work, one that was managing 45 does a third less, and one already drawing below 30 fps is untouched. With the kitty backend the pixels sent to the terminal fall with the frame count, which is what an ssh session pays for. Sitting still gets cheaper in the half-block backend, which redraws every frame whether or not anything changed, so a motionless model no longer costs full render work sixty times a second. What the frame loop paces slows to match, input latency most visibly: a keypress is noticed within 33 ms rather than 17. The fixed windows in the input and camera handling (escape-sequence reassembly, the held-key latch) keep their lengths but are only tested once a frame, so each can now overrun by up to 17 ms more than it did. `-f 60` restores the previous behavior.
- An ASCII-classified STL file containing a line longer than 64 KB is now rejected up front, because parsing such a line costs a large multiple of its size in memory (measured above 1 GB for a 52 MB single-line file). Such a line is either garbage or content the format ignores; no real STL comes near that length, since the format puts one short statement on each line. Files at or under 64 KB skip the extra check entirely, since they cannot contain a longer line.
- The HUD has been redesigned from a single left-aligned line of uniformly grey fields into a full-width status bar with three zones: the model name on the left, the render state (shading mode, the wireframe color when in wireframe shading, lighting, background) centered, and the toggle tags plus the live numbers (first-person speed, fps) aligned against the right edge. The `light:`, `bg:` and `wf:` field labels are gone: those values now stand alone in the centered group, separated by middle dots, since a lighting or background name needs no caption to be recognized, and only the units on the live numbers (`fp`, `fps`) are still spelled out. The background name is rendered dimmer than the fields before it, which both matches its being the first field dropped on a narrow terminal and keeps it distinct from the wireframe color, the one other field that can show the same word. Fields also carry a visual hierarchy instead of one color: values render brighter than the remaining labels and the separators, the active shading mode is shown in a soft cyan accent, the spin/cull/tex toggles are compact tags lit in the accent color when on and dimmed when off (replacing the `spin ON` and `cull: ON` word pairs), and in wireframe shading the wireframe color's name is rendered in that color. On a terminal too narrow for the full bar, fields are now dropped deliberately in order of how redundant each is with the picture itself, instead of clipping whatever crossed the right edge: the background name goes first, then the lighting mode, then the toggle tags, then the wireframe color name, then the model name's budget shrinks from 24 bytes to 12, then the whole centered group goes, then the name shrinks again to 8 bytes and is finally dropped, and last of all the first-person speed. What survives longest is the fps reading, which has no visual stand-in anywhere else; it is still shown on a terminal about ten columns wide. Narrower than that, the line runs past the edge and is clipped by the terminal as before, keeping a gap between whatever fields remain so they cannot run together. The bar is measured in terminal columns rather than bytes, so a name in a non-Latin script or an East Asian script still fills the bar to its right edge. The bar works within both 24-bit and 256-color output (its colors quantize through the same perceptual palette mapping as the render), uses no glyphs beyond ASCII and the middle-dot separator the old HUD already used, and shows shading mode names in lowercase like every other field. A model's filename is now sanitized before display, with each offending byte replaced by `?`: control characters, the C1 range a terminal can read as escape-sequence introducers, byte sequences that are not valid UTF-8 (a filename is an arbitrary byte string on Unix), and the invisible and direction-changing formatting characters, from the soft hyphen and the zero-width space to the bidirectional overrides and the tag characters, which can silently reorder or hide the rest of the name. An unchanged HUD line also no longer costs any output bytes per frame: it is re-emitted only when its content changes or the whole screen was redrawn.
- Long model names no longer crowd the HUD off the screen. The name is now shortened to 24 bytes by replacing its middle with `...`, so a longer one reads as `a_very_long...l_name.stl`. For a plain ASCII name that is 24 characters; a name written in a non-Latin script keeps fewer, since each of its characters costs more than one byte, but it is never cut inside a character. A name within the limit is shown unchanged. Previously the name was shown in full, and since the HUD is clipped at the terminal edge rather than wrapped, a long one pushed every field after it (spin, first-person speed, lighting, background, wireframe color, culling, texturing) off the right edge where they could not be read at all. The middle is cut rather than the end so the file extension survives, which the HUD does not show anywhere else; the trade is that two files whose names agree at the beginning and the end now show the same HUD name, and the full name is not displayed anywhere. On a terminal too narrow for even the shortened name alongside the other fields, the redesigned bar (see the entry above) drops whole fields by priority rather than clipping them, and shrinks this budget to 12 and then 8 bytes on the way down, dropping the name entirely at the narrowest widths so the fps reading survives.
- The Escape key no longer quits; `Q` (or Ctrl+C) is the quit key, matching the common terminal-application convention. Escape on its own now does nothing, and escape sequences the viewer has no binding for are ignored instead of quitting: previously any key the viewer does not bind but the terminal encodes as an escape sequence (function keys, the navigation and editing cluster, modified or application-mode arrows, alt chords), along with X10-style mouse clicks, terminal replies, and any sequence fragmented past the reassembly window on a slow connection, read as an Escape press and exited the viewer. Mouse reports were the exception, and in two different ways: an incomplete one was discarded silently, while a malformed one was cut short at whatever byte broke the format, so the rest of it was read as ordinary typing (the digits of a coordinate switching shading mode, for instance). Every such sequence is now consumed in full, including forms whose terminator is not a plain final byte (the Linux console's `ESC [ [ A`, counted X10 payloads, string-terminated replies), so they neither quit nor dispatch their trailing bytes as spurious keypresses. Input is now buffered and parsed as a unit, so a long reply, or one split across several frames by a slow connection, is still consumed whole rather than acted on halfway through. Some limits remain. A sequence longer than 1024 bytes, which in practice means a clipboard or status reply rather than a keypress, cannot be held in full; the viewer skips ahead to the end of it, so anything typed in the moment it takes to arrive is lost with it, including keys the terminal encodes as escape sequences (function keys, arrows, mouse clicks and drags). That covers a reply arriving in pieces with input landing between them, which is the ordinary case for a long one. Only the reply's own ending stops the skip; one that never ends at all keeps being skipped only while bytes keep arriving fast enough to look like a stream rather than a person (about 256 a second, roughly eight times what holding a key produces), and is given up on about two seconds after they fall below that. Typing does not hold it open; a mouse drag does, since the terminal sends those far faster, so a drag over a reply that never ends keeps that drag swallowed for as long as it continues. Ctrl+C still quits throughout, since it is a signal rather than a keypress. A short sequence whose bytes are spaced further apart than the reassembly window is given up on, and whatever of it arrives later is read as ordinary typing, because at that spacing it is indistinguishable from someone typing those same characters; a longer one is too long to be a keypress at all, so it is skipped to its end instead, on the same terms as an over-long one. The rest are cases where two different keystrokes send the same bytes and no decoder can separate them: Escape is the prefix of an alt chord, and the alt chords that begin a control sequence, an application-mode key or a terminal reply (alt with `[`, `O`, `]`, `P`, `X`, `^` or `_`) are prefixes in turn, so each of them absorbs what follows closely enough behind it (with an application-mode arrow, that means the camera moves). Typing the bytes of an escape sequence quickly by hand is read as that sequence. "Closely enough" is at least the 50 ms reassembly window, and widens two further ways: with the frame time, so a heavy model or a low `--fps` stretches it, and for as long as anything keeps arriving faster than that window, so holding a key extends it until the key is released. Arrow keys sent in application cursor mode (the SS3 `ESC O A` form) are now recognized as arrows, as is alt+arrow on terminals that send it as an escape prefix before the arrow; terminals that instead encode it as a modified arrow still ignore it.
- The `R` key now resets to the flag-specified launch state instead of factory defaults: shading, lighting, background, wireframe color, spin, backface culling, and texturing return to the values selected by their command-line flags (their defaults when not passed), joining the camera, which already returned to the `--yaw`/`--pitch`/`--zoom` view. The reset also now cancels a still-held camera movement key (WASD/arrows, `+`/`-`), which previously could keep moving the camera for up to 100 ms after the reset. With no flags passed the reset target is unchanged, since each of these flags defaults to its previous hard-coded reset value.
- `--cull` and `--texture` no longer take an `on|off` value; they are now paired boolean flags (`--cull`/`--no-cull` and `--texture`/`--no-texture`, with the later flag winning), in the same plain-boolean style as `--spin` and `--no-ao`. The `-c`/`-t` short flags and the boolean value spellings (`on`/`off`, `1`/`0`, `true`/`false`, `yes`/`no`, `y`/`n`) are removed with the value form: the `=` form (for example `--cull=on`) is now a does-not-take-a-value error, `-c`/`-t` are unknown-flag errors, and a space-separated token after the flag is no longer consumed as a value but read as the model operand.
- Interactive rendering now fails with a clear error, instead of emitting escape garbage, on any terminal it cannot draw to: stdin or stdout not being a terminal (piped or redirected, which previously also set raw mode on a non-terminal stdin), `TERM=dumb`, and Windows consoles that cannot enable VT escape-sequence processing. `--bench`, `--help`, and `--version` are unaffected and keep working with redirected stdio (with one Windows-only nuance: `--version` now switches the console to UTF-8 only when stdout is a VT-capable console, so when it is redirected, piped, or a legacy console, the code page is left untouched. The emitted bytes are UTF-8 either way; only display through a non-UTF-8 console shows the accented author name as mojibake).
- Lit surfaces now pass through a soft-knee highlight rolloff (tonemap) before display, so bright, untextured, flat-lit, or strongly-emissive areas no longer clip to flat white but keep their shading gradient. The curve is identity below the knee (0.7) and rolls off above it, so any channel lit past the knee (including a full-white lit surface) is pulled down somewhat while darker midtones and shadows are unchanged; unlit materials and UI (wireframe, HUD, background) are unaffected.
- Slightly smaller per-frame terminal output: the incremental redraw no longer writes a cursor-advance escape when a row's changed pixels are followed by an unchanged run reaching the right edge. The rendered result is identical; only the redundant escape (which the next absolute cursor move made a no-op) is dropped.

### Removed

- The 1-indexed numeric value aliases for `--shading`/`--bg`/`--lighting`/`--wireframe-color` (for example `-s 3` for `-s phong`, or `--bg 2` for `--bg gray`). Use the named values instead; a numeric value is now an invalid-value error.
- The shadow map and the `--no-shadow` flag. A single auto-fit model with no ground plane has nothing to receive a cast shadow, so the feature added load and per-frame cost without value to a model viewer. Lit surfaces now use all configured lights uniformly; baked ambient occlusion still provides crevice darkening. The default look is slightly flatter than before. Passing `--no-shadow` is now an unknown-flag error.

### Fixed

- Several valid STL files that were previously rejected now load. The loader classifies a file as ASCII or binary once and parses it with the reader for that format, where it previously handed the file to a vendored entry point that re-detected the format with a different heuristic, so a file the two heuristics disagreed on was parsed as the wrong format and rejected. Concretely: an ASCII file whose first `facet` keywords, or first line break, sit past the 256th byte (because of a very long solid name, or any other leading content before the first facet), and a binary file whose 80-byte header comment happens to mention words like `solid` and `facet normal` alongside a newline byte, both load now. An ASCII file opening with a blank line (Unix or Windows line endings) before `solid` also loads, as does one beginning with a UTF-8 byte-order mark: the format detection now skips both along with the spaces and tabs it already skipped. A capitalized `solid` keyword no longer prevents ASCII classification either (the facet keywords themselves must still be lowercase, which the format prescribes and the parser requires). Separately, format detection of a file shorter than the 80-byte STL header no longer examines bytes beyond what was actually read, which made the ASCII-or-binary classification depend on uninitialized memory; the only files whose classification those stray bytes could sway are ones whose readable bytes are whitespace, optionally ending in the first letters of `solid`, and such a file is rejected under either reading (it has no room left for any facet), so no load outcome changes.
- Input decoding no longer stalls rendering while a key sequence is still arriving. It used to wait mid-sequence for the next byte, up to 50 ms per byte, which paused the render loop whenever a sequence was split in transit: on a high-latency or busy connection, an arrow key or a mouse drag could visibly drop the frame rate. Decoding no longer waits on POSIX, so no amount of input stalls a frame there; what remains is the work of reading it, measured at 3.1 ms for a whole frame's worth of the most expensive input shape, against the 33 ms of a frame at the default cap. On Windows the console API it has to use offers no equivalent no-waiting guarantee.
- Mouse handling is steadier. A wheel notch sent with any modifier held now zooms; it was previously mistaken for a drag, which snapped the camera by the distance from wherever the pointer last was. A horizontal wheel is now ignored outright, rather than being read as that same spurious drag. A malformed mouse report is now ignored whole. Every form the SGR extension does not allow is rejected: one missing a coordinate or carrying a zero or absurd one, one whose button code is outside the eight bits the encoding has, a press or motion naming no button, a motion or wheel report in the release form, one carrying more parameters than the format has, and one whose parameters are not all numeric. (A release naming no button is still honored, since that is how some terminals report one, and any release ends a drag.) Previously these split two ways, and the more damaging half was the one that looked fine: a report whose parameters were all numeric was acted on whatever they said, and since a press sets the point a drag is measured from, nothing looked wrong until the camera jumped on the next motion report. A report the old scan could not read at all was instead cut short at the offending byte, leaving the rest of it to arrive as ordinary typing. Separately, a drag delta larger than the terminal is now treated as a discontinuity and re-seeded rather than orbited: no pointer moves that far in one report, and the parser cannot recognize such a coordinate because it has no way to know the terminal's size. A drag that begins without its opening report starts from the pointer's current position instead of jumping.
- Characters with no binding no longer cancel an in-progress held camera key. Previously any such character arriving while a movement key was held stopped the camera until that key was pressed again, which was most visible when pasting text or when a terminal reply arrived mid-movement. Pressing another key on the keyboard still stops the movement, and always will: the operating system repeats only the most recently pressed key, so the held key stops sending anything at all, which nothing the viewer does can change.
- On Windows, a console that cannot report its size no longer produces a garbled or one-column render: the query's failure is now detected (as is a console reporting an empty window rectangle) and the viewer falls back to 80x24, the same as on Linux and macOS. Previously the size was read from uninitialised memory when the query failed.
- STL models now load upright instead of pitched 90 degrees sideways. STL carries no orientation metadata and its ecosystem convention (CAD, 3D printing) is Z-up, while the renderer is Y-up; the loader now remaps STL coordinates to Y-up at load, matching the fixed per-format up-axis mainstream viewers use. OBJ and glTF are Y-up by specification and PLY is treated as Y-up, so those formats are unchanged.
- A `--threads`/`-j` value above the hardware thread count is now clamped to it everywhere. Previously only the render worker pool clamped: the `--bench` report header printed the unclamped request (for example `threads=999` while 16 workers actually ran), and model loading (ambient-occlusion baking, texture decode) could spawn the full requested number of threads.
- `--bench-size WxH` now rejects dimensions whose pixel count (`W * H`) would exceed the addressable range, instead of accepting them. Such a value previously crashed a 32-bit build (the pixel count wrapped a 32-bit `size_t`, producing a tiny framebuffer that rasterization then wrote past); 64-bit builds already failed on the oversized allocation. Each axis was, and still is, capped individually.
- Release builds (`-march=native`) no longer fail with newer Clang on AVX10-capable CPUs: Clang's benign "avx10.1-256 will be promoted to avx10.1-512" compiler warning was fatal under `-Werror`; it is now suppressed in both build systems (Clang only).
- Model files of 2 GB or more now load on Windows (file sizing used the C library's 32-bit `ftell` there, so a binary STL that large was always rejected at its file-size validation and a glTF external image that large failed to read; 64-bit Linux and macOS were unaffected). 32-bit builds, whose address space can never fit such a model, now report the normal load failure everywhere (previously 32-bit Windows misdetected the file at its size validation, and 32-bit Linux failed at opening it, since large-file `fopen` support was not enabled).
- Horizontal orbit no longer reverses when the model is viewed upside down: after pitching the camera past the top or bottom pole, dragging the mouse left/right (and the A/D and arrow keys) moved the model opposite to the input. The yaw input is now inverted while the view is upside down (matching Blender's turntable behaviour), so the model always follows the drag, including continuously through a drag that crosses a pole.
- The interactive HUD FPS counter read `0 fps` at startup (until the model was moved) and updated erratically, reading too low, at uncapped or very high frame caps. It discarded every frame faster than 1 ms, so on light models where nearly every frame is sub-millisecond the reading was never seeded. The smoothing threshold is fixed so sub-millisecond frames now count, and the displayed value is refreshed at a fixed ~10 Hz so it stays readable at high frame rates.
- glTF models using the ratified `KHR_meshopt_compression` extension (as opposed to the older draft `EXT_meshopt_compression` name) failed to load any real geometry, since the vendored `cgltf` only recognized the draft name. Refreshed `cgltf` to a current commit that parses both, and added decoding for the extension's `COLOR` vertex filter.
- glTF sparse accessors (`POSITION`/`NORMAL`/`TEXCOORD`/indices using the `accessor.sparse` override) previously read as zero/empty instead of resolving the sparse data, a latent bug in the same `cgltf` refresh above.

## [v0.1.0-alpha.1] - 2026-06-27

First public prerelease.

### Added

- CPU rasterization pipeline: model/view/projection transforms, perspective-correct triangle rasterization, z-buffer depth testing, backface culling, Blinn-Phong lighting, and order-independent alpha-blended transparency (exact per-pixel A-buffer)
- Shading modes: wireframe, flat, and Phong
- Shadow mapping (alpha-cutout aware) and baked ambient occlusion
- Texturing: bilinear sampling with per-texture wrap modes (Repeat/Clamp/Mirror), alpha cutout, and normal/metallic/emissive/occlusion maps
- Compressed texture and geometry support: KTX2/Basis (ETC1S/UASTC), WebP, Draco mesh compression, and meshopt-compressed buffer views
- Model formats: OBJ/MTL, PLY (ASCII and binary LE/BE), STL (ASCII and binary), and glTF 2.0 / GLB
- Multithreaded worker pool driving the opaque, transparent-accumulate, and resolve phases
- Unicode half-block (`▀`) output with 24-bit ANSI color; two vertical pixels per terminal cell
- Interactive controls: keyboard plus mouse drag-orbit and scroll-zoom, auto-rotation, and a HUD status line
- CLI flags for initial shading/background/lighting/wireframe color, culling, texturing, threads, frame cap, headless benchmarking, crease angle, and the `--no-shadow`/`--no-ao`/`--no-hud` toggles
- Cross-platform support: Linux, macOS, and Windows, including 32-bit (ILP32) builds
- Two build systems (Make and CMake) each with release, portable, and dist (self-contained) variants
